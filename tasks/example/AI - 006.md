## 2. What the latest discussion decided

From `AI - 005.md` (§7 answers):

- **Option 1**: split tables — `Empresa` (identity), **`EmpresaRelacionada`**
  (group role/roster, like `Cedente`), **`AnaliseRelacionada`** (per-analysis
  capture, like `AnaliseEmpresaSocio`).
- **`Cedente.empresaId` is no longer globally unique** → `@@unique([grupoId,
empresaId])`.
- **`AnaliseRelacionada` grain = per analysis** (`analiseId`), **not** per
  dossier.
- **Creation**: the **user adds per analysis** (no automatic copy from the
  roster).
- **`restricoes` lives on the analysis row** (not the roster).
- **Sócios of a relacionada** need a **snapshot** (`AnaliseRelacionadaSocio`),
  mirroring `AnaliseEmpresaSocio`, sourced from the live `VinculoSocietario`.
- **Relacionadas "just gain sections"** later (no docs, no member fan-out).
- **Dedupe on migration**: by `empresaRelacionadaId`, then normalized `cnpj`;
  **`GRUPO_ECONOMICO` wins**.
- **Roster**: written as a side effect of the analysis add, **shown read-only**,
  plus the **nicety** — the group's companies offered as CNPJ suggestions.
- **Endpoint home**: **on the analysis** (it can change per analysis), with a
  separate group roster read.

## 3. What was implemented (`0eec5db`)

**Schema + migration** (`backend/prisma/migrations/20260939000000_analise_relacionada/`)

- `EmpresaRelacionada` = group roster: `grupoId, empresaId, tipoRelacao`
  (`@@unique([grupoId, empresaId])`).
- `AnaliseRelacionada`: `analiseId, empresaRelacionadaId?, empresaId,
tipoRelacao, restricoes` (`@@unique([analiseId, empresaId])`).
- `AnaliseRelacionadaSocio`: frozen snapshot (`@@unique([analiseRelacionadaId,
socioId])`).
- `Cedente` unique → `(grupoId, empresaId)`.
- Backfill: old per-dossier rows that referenced an `Empresa` are folded into
  the roster + analysis rows (dedupe, `GRUPO_ECONOMICO` wins). Rows with only
  copied text are dropped.

**Backend**

- New `backend/src/modules/analise-relacionada/` (contract + Prisma repo +
  one file per action, services, controllers, routes, validation).
- Endpoints: `GET/POST /analises/:analiseId/relacionadas`,
  `PATCH /analises/:analiseId/relacionadas/:relacionadaId`,
  `GET/POST /analises/:analiseId/relacionadas/:relacionadaId/socios`,
  `GET /grupos/:grupoId/relacionadas`. Writes gated `MONTAGEM|ANALISTA|DIRETORIA`.
- The per-dossier relacionada code was removed from `analise-empresa`.
- Add reuses a stored `Empresa` (no registry call when known).

**Frontend**

- `api/credito.ts` + `api/types.ts`: `AnaliseRelacionada`, `EmpresaRelacionada`
  (roster), `AnaliseRelacionadaSocio` and the new functions.
- Hooks `useAnaliseRelacionadas`, `useGrupoRelacionadas`; `useDossie` no longer
  loads relacionadas.
- `RelacionamentosStep` (group step 5) rewritten: list + add + **Ver sócios**
  (`RelacionadaSociosPanel`).
- `RelacionadaForm`: CNPJ + tipo + restrições, **Buscar CNPJ** preview, and a
  `<datalist>` of roster companies (the nicety).
- Removed `RelacionadasList`, `useRelacionadasDaAnalise`.

**Docs:** README updated (diagram, §5, endpoints, wizard/group bullets,
implemented list, `Cedente` uniqueness, gaps).

## 5. Caveats and risks to remember

- **Migration drops cnpj-only rows.** Old `EmpresaRelacionada` rows with no
  `Empresa` link (only copied text) are not migrated. The seed creates none, so
  this is low impact, but any hand-entered data would be lost.
- **`AnaliseRelacionada` starts empty per analysis** (no auto-copy). That was the
  decision; if you later want continuity, add a "copy roster on create" step.
- **Roster `tipoRelacao` is not updated** by a later add with a different type
  (the upsert keeps the first). Revisit with item 4.
- **`restricoes` is analysis-only**, so the same company can have different
  restrictions per analysis — intended.
- **The test DB was migrated** with `20260939000000` during development; the dev
  DB still needs it applied (`prisma migrate deploy`).
