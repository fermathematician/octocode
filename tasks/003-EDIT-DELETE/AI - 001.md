---

## TL;DR

Calendar **tasks** already had edit/delete + a done checkbox (AI-001). This task closes the
remaining edit/delete gaps: **stories** (new `DELETE /stories/:storyId`, plus a full edit form on
both the backlog and kanban modals), **sprints** (edit name/dates from the Sprints screen), and
**projects** (rename/recolor and delete from the project header). No database migration was needed:
`Commit.storyId` is already `onDelete: SetNull`, so deleting a story keeps its commits.
Backend: 120 tests pass. Frontend: typecheck/lint/build pass.

## 2. What was implemented

**Phase 1 — backend story delete**

- `StoryRepository.delete(id, ownerId)` (contract + Prisma impl via
  `story.deleteMany({ where: { id, project: { ownerId } } })`).
- `DeleteStoryService` (404 when the actor owns no such story).
- `DeleteStoryController` → `204`.
- `DELETE /stories/:storyId` wired in `stories.routes.ts` and `composition/stories.ts`.
- `InMemoryStoryRepository.delete` + 3 unit tests (`DeleteStoryService`).

**Phase 2 — frontend story edit/delete**

- `api/stories.ts`: `deleteStory`, `moveStoryToSprint`.
- New shared `components/stories/StoryEditForm.tsx` (title, points, priority, sprint) with per-field
  validation and ApiError display. Replaces the point-only `StoryPointsEditor` in both modals
  (deleted).
- `StoryDetailModal` (backlog) and `StoryCommitsModal` (kanban) now use the form, take
  `sprints`/`onMoveToSprint`, and expose a **Delete story** action with a confirm.
- `useBacklog` / `useKanban`: load sprints, expose `moveToSprint` and `removeStory` (local state
  update on success); modals close on delete.

**Phase 3 — frontend sprint edit**

- `api/sprints.ts`: `updateSprint(sprintId, input)`.
- New `components/sprints/SprintForm.tsx` extracted from `CreateSprintModal`; new
  `EditSprintModal` reuses it with `initialSprint`.
- `useSprints.editSprint`; `SprintCard` gained **Edit**; `SprintsPage` owns the editing state.

**Phase 4 — frontend project edit/delete**

- `api/projects.ts`: `updateProject`, `deleteProject`.
- New `components/project/ProjectEditModal.tsx` (name + `type="color"`); `TextInput` accepts
  `type: "color"`.
- `ProjectPage` header shows **Edit project** / **Delete project** when a project is selected;
  `App.tsx` adds `handleProjectUpdated` / `handleProjectDeleted` (removes it, clears
  `activeProjectId`, returns to All projects).

**Docs:** README §5.5, §6.6, §9, §11, §14.2 updated; this AI doc + `001.md` created.

## 3. Decisions

| Decision | Rationale |
| --- | --- |
| Story delete keeps commits (`storyId` set null). | `Commit` is unique per `[repositoryId, branch, sha]` and can be re-linked by a later sync; no schema change/migration. |
| One shared `StoryEditForm` used by backlog + kanban. | Avoids two divergent edit UIs; both modals stay thin. |
| `StoryPointsEditor` removed. | It was only used by the two modals and is fully superseded by the form. |
| Sprint form extracted with `initialSprint?`. | Mirrors the `CalendarEventForm` refactor from AI-001; one validation path for create/edit. |
| Project edit/delete lives in the project header (not the sidebar). | The sidebar is navigation-only today; the header already owns project actions (`Add project`). |
| Confirmation via `window.confirm`, errors via inline text / `window.alert`. | Matches the existing `SprintsPage`/`CalendarPage`/`TodayTable` conventions; no new modal infrastructure. |

## 7. Caveats and risks

- **Delete is irreversible.** Story delete keeps commits (`SetNull`); project delete cascades to
  stories, commits, local branches and the repository link.
- **Story edit always sends title/points/priority** (the backend rejects an empty update body), so a
  sprint-only change still rewrites the other three fields with identical values.
- **Duplicate branch rename** still surfaces the backend `409` (P2002 mapping), unchanged.
- **Editing sprint dates** changes the active-sprint selection and the burndown (expected).
