## TL;DR

Calendar **tasks** can now be edited (type/title/date/start time) and deleted, and have a **done**
checkbox, on both the **Today** table and the **Calendar** day panel. Scope is tasks only
(`type === "task"`); reminders/meetings stay read-only in the frontend. The backend already exposed
`PATCH`/`DELETE /calendar-events/:eventId`; the only schema change is a local-only
`CalendarEvent.completed Boolean @default(false)`. Routes were **not** added. README updated.

## 1. Scope and interpretation

| Question from planning | Answer |
| --- | --- |
| What are "tasks"? | Calendar items (`CalendarEvent`), not kanban stories. Confirmed by the user. |
| Which event types get the checkbox/edit UI? | Only `type === "task"` ("only tasks for now"). |
| Are new routes needed? | No — `PATCH` and `DELETE /calendar-events/:eventId` already existed. |

Assumption kept: the `completed` flag is stored for any event by the backend (structural), but the
frontend only surfaces it for tasks.

---

## 2. What changed

**Backend**

- `CalendarEvent.completed Boolean @default(false)` + migration
  `20261004000000_calendar_event_completed`.
- `optionalBoolean()` helper in `shared/validation.ts`; `parseUpdateCalendarEventBody` accepts
  `completed` and rejects non-booleans.
- `UpdateCalendarEventData.completed`; `UpdateCalendarEventService` maps it.
- `CalendarEventDto.completed` exposed by the presenter.
- Google sync is untouched: `upsertByExternalId` never reads/writes `completed`, so completion is
  local-only and survives a sync.

**Frontend**

- `api/calendar-events.ts`: `updateCalendarEvent`, `deleteCalendarEvent`, `UpdateCalendarEventInput`.
- New shared `Checkbox` component.
- `CalendarEventForm` moved to `components/calendar/` and extended with an optional `initialEvent`
  for edit mode (prefilled values, "Save changes").
- New `CalendarEventEditModal` (wraps `Modal` + form; calls an `onSave` callback so the page/hook
  owns the request).
- `useCalendarEvents` / `useTodayAgenda`: `updateEvent`, `removeEvent`, `toggleCompleted`.
- `TodayTable` and `CalendarEventList`: checkbox + Edit/Delete for task rows; completed rows use a
  struck-through title. Delete uses `window.confirm` (same as `SprintsPage`).
- `CalendarPage` / `TodayPage`: edit-modal state wiring.

**Docs:** `README.md` §3.1, §5.5, §6.3, §6.6.

## 3. Decisions

| Decision | Rationale |
| --- | --- |
| Reuse the existing generic `PATCH` with `completed` instead of a `/completed` route. | Matches the existing calendar update contract; no new route/middleware. |
| `completed` is local-only (not pushed to Google). | Google has no equivalent and conflict policy is "local wins" for local data. |
| Move `CalendarEventForm` to `components/calendar/`. | It is now shared by Calendar (create) and the edit modal; mirrors `components/sprints/`. |
| Edit UI restricted to `task` rows. | User said "only tasks for now". |
